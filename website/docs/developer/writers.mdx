# Working with writers

Docs and code live in the same repo (`website/docs` vs `src/`). A writer should be able to run [Quickstart](/docs/quickstart) without asking you for a Zoom.

## What to send when a route changes

In the PR description, or a short comment:

- method + path
- auth or not
- one real request
- one real response (copy from your terminal)
- status codes you added or removed

A screenshot of Postman without the JSON is not enough.

## What writers will ask

- "Is the key in the header or in the query?" → header `X-API-Key`
- "Can I use `wip` as status?" → no, only `todo` / `doing` / `done`
- "Why is my GET 404 with id `1`?" → the id must be a UUID

If you don't know, say so. Don't invent a status code.

## Review

Writers review `website/docs/**`. You review `src/**`. Cross-read the snippets. A command that 401s on a clean clone is a bug in the page, not "the reader is wrong".
