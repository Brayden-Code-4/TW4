# Developer guide

This section explain how to hook TW4 into your own code. There is no official SDK. You talk HTTP and JSON.

If you only want to click around with curl, use the [User guide](/docs/user-guide). This part is for people who write a client or change the server.

## What we asked a teammate

I sat with another student who already called TW4 from a Node script. Seven questions, short answers.

**What is this API for?**  
Keep a writing backlog as tasks. Not a full project manager. Title + status, that's it.

**What do I need first?**  
Node 20+ (or Docker), a `.env` with `API_KEY`, and the server running on port 3000. Reads work without a key. Writes do not.

**Is there an SDK?**  
No. `fetch` in Node 20, or `urllib` in Python. Wrap it yourself if you call it a lot. See [Integrate](/docs/developer/integrate).

**What are the defaults?**  
`HOST=0.0.0.0`, `PORT=3000`, `status=todo` when you omit it, `DATA_FILE=./data/tasks.json`, `LOG_LEVEL=info`. Empty `API_KEY` is a `500`, not a silent open API.

**Where does it break?**  
PowerShell mangles JSON braces. A task id that is not a UUID returns 404 (the regex never matches). Filter `?status=wip` is 400. Forgetting `X-API-Key` on POST is 401.

**How do errors look?**  
Always JSON: `{ "error": "...", "message": "..." }`. Codes: 400, 401, 404, 500. No HTML error pages.

**If a writer documents a route and I change it?**  
Tell them before you push. They need the method, path, auth, and one real response. See [Working with writers](/docs/developer/writers).
