# Use the TW4 API

How-to page. The API is already running (see [Installation](/docs/installation)). For method tables, status codes and OpenAPI, use the [API reference](/docs/api/overview) — do not demo both pages in a row; they repeat the same curls.

Base URL on your machine: `http://127.0.0.1:3000`.

Reads are open. Creates, updates and deletes need header `X-API-Key`, same value as `API_KEY` in `.env`. Treat that as **local only**: anyone who reaches the port can list the backlog.

## Health

```bash
curl http://127.0.0.1:3000/health
```

`"status":"ok"` means the process is up. It does not mean your key is valid.

## List and filter

```bash
curl http://127.0.0.1:3000/api/v1/tasks
curl "http://127.0.0.1:3000/api/v1/tasks?status=todo"
```

`status` must be `todo`, `doing` or `done`. Anything else returns `400`.

Get one task: `GET /api/v1/tasks/<TASK_ID>`. Unknown id → `404`. The id must be a UUID, not `1`.

## Create, update, delete

Full snippets (cURL, JavaScript, Python) live on:

- [POST /api/v1/tasks](/docs/api/create-task)
- [PATCH and PUT /api/v1/tasks/\{id\}](/docs/api/update-task)
- [DELETE /api/v1/tasks/\{id\}](/docs/api/delete-task)

Minimal PATCH (PowerShell users: see the create page for `ConvertTo-Json`):

```bash
curl -X PATCH http://127.0.0.1:3000/api/v1/tasks/<TASK_ID> \
  -H "Content-Type: application/json" \
  -H "X-API-Key: change-me-now" \
  --data-binary '{"status":"doing"}'
```

`PUT` is the same handler. Send only the fields you change.

## Errors you will actually hit

| Code | When |
| --- | --- |
| `400` | Bad JSON, empty title, or a status that is not allowed |
| `401` | Missing or wrong `X-API-Key` |
| `404` | Wrong path or unknown task id |
| `500` | `API_KEY` is empty in the environment |
